## 二、整体架构：管理员身份链

```
用户输入账号密码
       │
       ▼
  POST /users/login
  后端返回 { access_token, user: { ..., role: "admin" } }
       │
       ▼
  login_page.dart 解析 user.role
       │
       ├─ role == "admin"  →  pushReplacement → AdminNewsPage
       └─ role == "user"   →  pushReplacement → MainScreen（普通用户首页）
```

**两处入口均做了分流**：
1. **登录成功时**（`login_page.dart` 第 65 行）：`if (user.role == 'admin')` → `AdminNewsPage`，else → `MainScreen`
2. **冷启动恢复登录态时**（`main.dart` 第 170 行）：`appProvider.currentUser?.role == 'admin'` → `AdminNewsPage`，else → `MainScreen`

这样即使已登录用户关闭浏览器后重新打开，只要 token 未过期，管理员仍会直接进入后台。

## 四、NewsApi 新增三个管理员方法

在 [news_api.dart](file:///d:/Code/Flutter/huinong_web/lib/api/news_api.dart) 中新增，复用已有的 `DioClient` 单例，自动携带 JWT Token：

### 4.1 创建资讯 `createNews()`

```dart
Future<News> createNews({
  required String title,
  required String content,
  String? category,
  String? coverUrl,
})
```

- POST `/news`，请求体为 `{title, content, category?, cover_url?}`
- 响应经 `DioClient` 拦截器自动剥离 `{code, message, data}` 包装，返回 `data` 中的资讯对象
- 通过 `News.fromJson()` 反序列化

### 4.2 更新资讯 `updateNews()`

```dart
Future<News> updateNews(int id, {
  String? title, String? content,
  String? category, String? coverUrl,
})
```

- PUT `/news/$id`，仅发送非空字段（部分字段更新）
- 响应为空时抛出 `ApiException` 防御

### 4.3 删除资讯 `deleteNews()`

```dart
Future<void> deleteNews(int id)
```

- DELETE `/news/$id`，无请求体
- 操作成功返回 void，失败抛出异常

> 同时修复了所有路径的尾部斜杠问题（`/news/` → `/news`），避免 FastAPI 307 重定向导致 PUT/DELETE 方法丢失。

## 五、管理页面 `AdminNewsPage` 详细说明

文件：[admin_news_page.dart](file:///d:/Code/Flutter/huinong_web/lib/pages/admin/admin_news_page.dart)

### 5.1 页面布局

```
┌─────────────────────────────┐
│  AppBar: "管理后台 - 资讯管理"   │  ← 右侧退出登录按钮
├─────────────────────────────┤
│  [分类筛选 Dropdown] [新增按钮] │  ← 工具栏区域
├─────────────────────────────┤
│  ┌─ Card ──────────── [✏] [🗑] │
│  │ 封面 | 标题            │  │
│  │      | 分类 时间 阅读   │  │  ← 可滚动列表（分页+下拉刷新）
│  ├─────────────────────────┤
│  │  ...更多资讯...         │  │
│  └─────────────────────────┘  │
└─────────────────────────────┘
```

### 5.2 状态管理

| 状态变量 | 类型 | 用途 |
|---------|------|------|
| `_newsList` | `List<News>` | 已加载的资讯数据 |
| `_skip` | `int` | 分页偏移量 |
| `_hasMore` | `bool` | 是否还有更多数据 |
| `_isLoading` | `bool` | 加载中标记，防止重复请求 |
| `_selectedCategory` | `String?` | 当前选中的分类筛选（null 表示全部） |

### 5.3 资讯列表加载逻辑

`_loadNews({bool reset = false})`：

1. **防重入**：`if (_isLoading) return;`
2. **重置模式**（reset=true，下拉刷新时）：清空 `_newsList`，重置 `_skip=0`，`_hasMore=true`
3. **追加模式**（上拉加载更多时）：调用 `NewsApi.instance.getNews(skip: _skip, limit: 10)`
4. **分页控制**：返回数据后 `_skip += 新数据条数`；当 `_newsList.length >= total` 时设 `_hasMore=false`
5. **错误处理**：捕获异常后调用 `ErrorHandler.showErrorSnackBar` 显示友好提示

上拉加载通过 `ScrollController` + `_onScroll()` 监听：当滚动到距离底部 100px 且 `_hasMore && !_isLoading` 时触发加载。

### 5.4 分类筛选逻辑

通过 `_filteredNews` getter 实现**前端本地过滤**（不从后端重新拉取）：

```dart
List<News> get _filteredNews {
  if (_selectedCategory == null || _selectedCategory == '全部') {
    return _newsList;                               // 全部
  }
  return _newsList.where((n) => n.category == _selectedCategory).toList();
}
```

工具栏的 `DropdownButtonFormField` 提供选项：全部 / 政策 / 农技 / 市场 / 预警。选择后调用 `setState` 触发 UI 重新渲染，`ListView.builder` 遍历 `_filteredNews`。

### 5.5 新增/编辑弹窗（共用 `_showEditDialog`）

通过 `existing` 参数区分模式：
- `existing == null` → **新增模式**，Dialog 标题"新增资讯"，表单为空
- `existing != null` → **编辑模式**，Dialog 标题"编辑资讯"，表单预填当前内容

弹窗使用 `StatefulBuilder` 为 Dialog 提供独立的状态管理，UI 结构：

```
┌─ AlertDialog ──────────────────┐
│  标题："新增资讯" / "编辑资讯"       │
│  ┌─ TextField（标题）            ─┤
│  ├─ TextField（正文，多行）        ─┤
│  ├─ DropdownButton（分类）        ─┤
│  ├─ TextField（封面URL，可选）     ─┤
│  └─ [取消]  [确认]               ──┤
└────────────────────────────────┘
```

**提交流程**：
1. 校验标题和正文非空
2. `setDialogState(() => saving = true)` 禁用按钮并显示加载圈
3. 按模式调用 `NewsApi.instance.createNews()` 或 `updateNews()`
4. 成功后 `Navigator.pop(ctx)` 关闭弹窗，然后通过 `WidgetsBinding.instance.addPostFrameCallback` 延迟到下一帧执行 `_loadNews(reset: true)` 刷新列表
5. 失败时 `ErrorHandler.showErrorSnackBar` 提示
6. `finally` 中恢复按钮可用状态

### 5.6 删除确认弹窗（`_confirmDelete`）

1. `showDialog<bool>` 弹出确认框，显示"确定要删除「xxx」吗？"
2. 用户点"删除"返回 `true`，点"取消"/遮罩返回 `false`/null
3. 确认后调用 `NewsApi.instance.deleteNews(news.id!)`
4. **乐观删除**：成功后在本地 `_newsList` 中移除对应项（`removeWhere`），避免重新网络请求加载全部数据
5. 失败时不影响列表状态，仅显示错误提示

### 5.7 UI 状态视图

列表根据四种状态显示不同视图：

| 条件 | 显示内容 |
|------|---------|
| `_isLoading && _newsList` 为空 | 居中 `CircularProgressIndicator` |
| `_newsList` 非空但 `_filteredNews` 为空 | "该分类下暂无资讯" |
| `_newsList` 为空 | "暂无资讯，点击新增" |
| 正常有数据 | `ListView.builder` + 底部加载圈 |

### 5.8 资讯列表项（`_buildNewsItem`）

每条资讯以 `Card` 展示，水平排列：
- **左侧**：封面缩略图（80×60，`Image.network` + 加载失败兜底图标）
- **中间**：标题（2 行截断）+ 分类标签（绿色背景）+ 发布时间 + 阅读量
- **右侧**：编辑按钮 + 删除按钮（红色）

## 六、技术要点

1. **复用基础设施**：`DioClient`（含 JWT 拦截器自动注入 Token）、`AppProvider`（登录态管理）、`ErrorHandler`（统一错误提示）、`SecureStorage`（Token 安全存储）全部直接复用，无需重新开发。

2. **Token 鉴权透明**：所有增删改请求由 `DioClient` 的 `AppInterceptor` 自动从 `flutter_secure_storage` 读取 Token 并注入 `Authorization: Bearer <token>` 头，前端业务代码无需关注。

3. **普通用户无法访问**：由于管理后台入口由 `role` 字段控制路由跳转，普通用户（`user` 角色）登录后直接进入 `MainScreen`，无从访问管理页面。同时后端 JWT 校验 `role=admin` 作为第二道防线。

4. **空安全**：所有模型和方法参数均使用 Dart 3 空安全语法（`?`、`required`、`late`）。
